# Size It Up: agent guide

## Read and work

1. Read [README.md](README.md), then the relevant part of [ARCHITECTURE.md](docs/ARCHITECTURE.md).
2. For map/assets or UI work, read [STUDIO_SETUP.md](docs/STUDIO_SETUP.md) or [UI_AUTHORING.md](docs/UI_AUTHORING.md).
3. Inspect the actual entry point, implementation and config before editing. This checkout can contain substantial uncommitted work; preserve unrelated changes and do not reset or stage the whole repository.
4. Current user instructions take precedence. The architecture guide separates observed code from unresolved owner requirements; do not mistake an existing implementation for authorization to override those requirements.
5. Keep this file short. Update the relevant section in place; never append a running history of "latest" rules. Keep tunable values in their owning config rather than duplicating them throughout the docs.
6. The owner requested removal of tests and unnecessary scaffolding. Do not recreate a test suite as routine cleanup. Validate affected behavior using syntax checks and the focused Studio checklist, and report what actually ran.

## Boundaries

- Main and AFK places have separate source roots and bootstraps. Never connect the main roots to the AFK place.
- The server owns seating, modes, deadlines, guesses, scoring, hearts, rewards, purchases and saves. Clients present snapshots and send validated requests. Preserve ownership, live-seat, match/round/turn ID, finite-number, bounds, deadline, throttle and replay checks.
- Keep true measurements in `Server/Config/ObjectMeasurements` and original server assets. Public previews must strip scripts/private metadata without altering source assets. ServerStorage.Objects import scale is never trusted: ObjectVisual removes fully transparent undecorated helper/root parts before measuring, preserves nested visible geometry and transparent decal surfaces, normalizes every replicated preview to exactly one visible stud and attaches only non-secret bounds diagnostics. ObjectLibrary rejects previews that fail this invariant. PreviewController applies ReferenceMeters or the current guess times StudsPerMeter, preserving relative real-life scale, shared display capping, grounding and answer privacy. Never bake private target measurements into replicated templates. Do not reintroduce removed prehistoric objects.
- Preserve authored furniture, scenery, eggs and screen UI. Never generate a replacement lobby, chair row or screen. Only remove identifiable runtime-owned/generated content; retain unrelated geometry.
- Reuse named UI and templates, copied resting poses, existing viewports and cameras. Missing required controls must report their path. Narrow exceptions for rulers, viewport dependencies and approved content filling are described in the UI guide.
- ReferenceMeasurement and MysteryMeasurement use the dedicated ZIndex 0 ruler layer beneath every authored HUD panel. Each projected height uses bold white rounded vertical segments with a two-pixel black outline and wider white/black top and bottom caps. Stack the object name above the metre/unknown value; when a reveal has a player mugshot, reserve space for it below that text and above the top cap. Allow HUD overlap and never displace rulers around header/slider/hearts; scale markers, names, measurements and reveal mugshots for mobile, clamp caption stacks inside top/side screen edges, and only separate the two ruler captions from each other. Preserve projection, privacy, grounding and cleanup.
- Use existing render loops. Rebinding/teardown must disconnect handlers, destroy owned clones/effects and restore camera, lighting, input, visibility, poses and modified part properties. Duplicate snapshots must not restart effects.

## Gameplay contracts

- The supplied owner requirements activate authored 2v2/3v3 assemblies only. Preserve 4v4 furniture while rejecting four-seat bindings and clearing its stale ScaleTable tags/runtime displays. Order nested seats by SeatIndex/Seat1-3, with stable spatial fallback; never replace, rename or reparent furniture. Table.Top's upper surface takes placement priority.
- Mode voting is seat-bound and invalidated by roster/death/order changes. Freeze the selected mode at match start. Preserve lowest-score ties, Best of Five raw-score totals/draws, terminal outcomes and departure/reward guards. See the architecture discrepancy table before changing default-mode or early-vote behavior.
- One living player guesses at a time. Rotate the next round's starter to the next living seat, while keeping result arrays in original seat order and local-first presentation stable.
- Preserve pair variety/history, no self-pairs and the private 4:1 compatibility limit. Send broad guess bands; lock the visible, bounded value, not a queued destination. Held dragging and explicit +/- clicks resize; release/cancel stops travel. Keep speed limits, shared floor, visible bounds and camera framing.
- The ObjectArena comparison camera uses the original adaptive two-object framing from CameraPart: it smoothly changes distance/FOV to keep the current reference and mystery bounds visible across viewport sizes. `ReferenceSpawn` and `TargetSpawn` are anchored authored BaseParts whose positions, spacing and orientation must be preserved; the server validates and reads them but never creates or moves them. The state HUD uses the restored `AdjustingSize.Right.Container` with `Track`, `Minus` and `Plus`; Track owns drag input and an optional nested `Knob`, while Minus/Plus keep the bounded 10% nudges. `ObjectArena.ButtonModel` is not a gameplay dependency. Keep the separate table reaction camera and do not restore rotate/view buttons.
- MatchController does not reparent world instances during a match. Leave authored world objects under their existing parents for the entire client lifecycle. Bot reaction cameras/effects resolve only live Workspace characters, excluding viewport WorldModels even when cached. Strip runtime tags and ScaleBotUserId from mugshot clones before parenting them.
- Normal round heart deductions settle once at TABLE_REACTION after the table-camera return. Pet healing respects the mode's life cap. Departures cannot reverse a scored terminal winner or duplicate rewards. Keep completion/ejection and match-cancellation handling distinct.
- A visible lost-heart `+` can buy a refill at any point in a live non-BestOfFive match, including watched turns, reveal, table return and reaction. Validate the authoritative live MatchId, membership, departure and heart cap; permit zero-heart recovery before match completion. Round/turn IDs are advisory for this purchase so a delayed receipt can still refill within the same match. Prevent overlapping prompts and clear cancelled requests.
- Every hint shows the same private exact-size yellow highlighted mystery clone, including paid purchases, saved credits and pet hints; never substitute directional advice. Send Actual only in the active guesser's hint snapshot, keep shared display scaling/floor alignment and camera framing, and clean up on expiry, lock, turn change or teardown. Preserve credit/receipt checks, configured duration/use limits and no deadline extension. Mystery rulers stay ???m during guessing; only reveal shows answer/guess metres.
- Preserve lobby HUD visibility while seated before the match; Busy purchase/equipment restrictions are separate from InGame presentation. Compact Header owns status/countdown; TimeLeft and hidden Profile are optional. Keep short, friendly copy and measurement-name suffix cleanup.
- Tutorials are removed, including the new-player seat guide, beam and red arrow. Do not recreate tutorial UI, remotes, completion flags or forced tutorial bot matches. Ordinary Play Bot behavior remains independent.

- GameStatesUI uses AdjustingSize.Left.Players.P1-P4 for all live player stats. P1 is always the local client and P2-P4 are the other seated players in local-first order; never bind the legacy Left.Hearts or Left.Points. Each card switches its own hearts/points by mode. During result reveals, scores from 75 upward receive a short server-clocked upward praise pop, with stronger colour and spark bursts at higher tiers; repeated snapshots do not restart it and the existing PERFECT result-card effect remains.
- Water touches must preserve health, release seating, clear velocity and keep feet above the destination. Bind only BaseParts named Water under Workspace.Map; accept real player characters and CollectionService-tagged ScaleBot characters, ignore unrelated NPC/dead/stale characters, debounce 0.75s and restore CanTouch on teardown. Bots keep only HumanoidRootPart touch-enabled and cancel their stale MoveTo target after teleporting. The requested destination is the nearest authored RespawnPoint, then assigned/default spawn.
- ChairTagController disables authored chair-shop Highlights and BillboardGui tags client-locally for the same active-match lifetime, then restores each instance's captured Enabled state on lobby return and teardown. Newly discovered chair visuals must follow the current state.
- NPCPopulationService owns fake lobby players cloned from direct Model children of ServerStorage.NPCs. Generate unique, Roblox-valid usernames from varied gamer-handle styles and separate varied DisplayNames; never return to a short pool of plain first names. Keep their negative internal UserId separate from the randomized positive AvatarUserId used by mugshot snapshots; never index AvatarUserId directly on a real Player, which must use UserId. Preserve per-NPC movement personalities, speed acceleration/deceleration, softened stationary turns, slight waypoint variation, jump preparation, blocked-path retries, varied curved routes, local/social/attraction walks, pauses, randomized cosmetic changes, spawn-point arrival/departure churn, the minimum roaming crowd and verified seating. Bots now use the normal Roblox SeatWeld height (`GameConfig.NPCPopulation.SeatDownOffset = 0`), two studs above the removed custom lowering; do not move authored seats or affect real players. Fake activity chat uses one global schedule: 75–160 seconds between due slots, 35% silent slots and a 24% chance of an extra 120–300 second quiet period, with pet/chair types biased away from immediate repetition. Keep server network ownership and bounded repathing so multiple NPCs do not jitter or continuously recompute paths. A lone human table gets one 95% NPC-response plan and enough responders to fill up to three seats. Managed ambient NPCs may fill and finish NPC-only matches. The Play Bot button uses PracticeBotService to create an obvious, temporary Bot with the legacy bot mugshot and no ambient identity, cosmetics, roaming state or population ownership; it leaves when its requesting human leaves. Keep all bots out of Players, persistent profiles, DataStores, purchases, analytics and platform player counts. Ambient identities/cosmetics live only in the runtime inventory-profile map.
- P1 Hearts.1/2/3 TextLabels are refill controls. Bind all three, show only the next missing heart, and keep it hidden when that heart was lost in the current TABLE_REACTION until the local player's `ReactionCycle.Beats.Heart + HeartSeconds` animation has completed. A zero-heart player may use Heart.1 during the remaining live reaction window; preserve server MatchId/membership/mode validation and receipt authority.
- During a bot GUESSING turn, opening the Sabotage developer-product prompt freezes bot movement/locking and preserves a full GuessSeconds on its deadline until MarketplaceService reports the prompt closed. Replan from the visible guess on release; support multiple watchers, cancellation, departure and a bounded missing-event timeout. Never hold a human guess turn or apply an unreceipted purchase.
- Keep two managed NPCs roaming by default and allow the others to wait at tables longer; table seeking and NPC-only completion use the NPCPopulation config. Bot match difficulty freezes one outcome plan from real participants' saved Matches, Wins and BestChainRound: new players receive a close match favoring their final win, skilled players receive a 50/50 human-win roll, and intermediate players use the configured blend. Early rounds may swing either way; final-heart/final-round targeting follows the frozen outcome with small score margins and variation. Never rewrite scores or winners directly.
- Each server chooses a stable displayed-population target of 12–15, yielding 11–14 managed NPCs with one real player and removing NPCs one-for-one as humans join. Keep two roamers by default while available extras seek tables. NPCPopulationService may publish rate-limited, catalog-backed BotPet/BotChair/BotWin packets through the existing ChatNews remote; activity updates the chosen NPC's runtime cosmetics/stats and never touches persistent profiles, receipts or real-player announcements.

## Saves, economy and pets

- Never overwrite a failed profile load with defaults. Preserve leased saves, receipt deduplication, durable transfer/referral journals, legacy ownership and reconciliation. Save grants before acknowledging receipts. Never trust client balances, rewards, destinations or purchase completion alone; zero product IDs must not prompt.
- Keep these copies byte-identical across main/AFK: Services/ProfileService, ProfileSchema, TravelService, PetProgressionService; Config/CosmeticCatalog, PetDatabase; Util/WealthScale. Keep the shared DataStore name aligned too.
- AFK entry requires five saved Wins. Enforce it in the main portal/action with an alert and again in AFKRuntime before starting a reward session.
- Pet XP counts online equipped time once per unique owned type, including AFK; duplicates share XP. Ability progress is separate: a frozen unique match roster, once per living owner's turn, persisted remainder, no watching/AFK/offline credit or fabricated history.
- Preserve pet names through PetDisplayName, rarity styles, source models, abilities and cleanup. Level-only updates should update existing labels rather than rebuild previews. The supplied follower requirement is one symmetric rear arc; see the implementation difference in architecture.
- Prices, currencies, odds, IDs and perks belong to their catalogs. Preserve paid-random checks, saved unopened blocks, single-use tokens and transaction guards. Do not infer "free" from a zero value in an unused currency field.
